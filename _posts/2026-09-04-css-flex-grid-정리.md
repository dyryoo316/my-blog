## 들어가며

오늘은 `02_CSS` 폴더에서 두 가지를 실습했다. 하나는 여러 선택자가 겹칠 때 어떤 스타일이 이기는지 정해주는 **선택자 우선순위**, 다른 하나는 요소를 가로/세로로 배치하는 두 가지 방법인 **Flexbox**와 **Grid**다. 특히 Flex와 Grid는 "왜 컨테이너에 `display`를 줘야 하는지", "축이 뭔지"가 헷갈렸던 부분이라 예시 코드와 표로 정리해둔다.

## 1. 선택자 우선순위

같은 요소에 여러 스타일이 동시에 적용될 때, CSS는 아래 순서로 우선순위를 따진다. 순위가 높을수록 이긴다.

| 순위 | 선택자 |
|---|---|
| 1 (최우선) | `!important` |
| 2 | 인라인 스타일 (`style="..."`) |
| 3 | id 선택자 (`#id`) |
| 4 | class 선택자 (`.class`) |
| 5 | 태그 선택자 (`div`, `p` 등) |
| 6 (최하위) | 전체 선택자 (`*`) |

> 실습해보니 `.test2 { background: darkorange !important; }`처럼 `!important`를 붙이면 id 선택자나 인라인 스타일보다도 우선순위가 높아져서, 나중에 다른 스타일을 덮어쓰기 위해 남발하면 유지보수가 어려워질 수 있겠다는 생각이 들었다.

## 2. Flexbox — 한 줄로 세우고 정렬하기

`div`만으로 영역을 나누면 가로축을 전부 차지해버리고, 화면 크기를 바꿔도 유연하게 배치되지 않는다. 이 문제를 해결하는 첫 번째 방법이 **Flexbox**다.

핵심은 **`display: flex`를 아이템이 아니라 아이템을 감싸는 상자(컨테이너)에 줘야 한다**는 것이다. 감싸는 상자를 플렉스 컨테이너, 그 안의 카드 하나하나를 플렉스 아이템이라고 부른다.

플렉스에는 두 개의 축이 있다.
- **주축(main axis)**: `flex-direction`이 정하는 방향
- **교차축(cross axis)**: 주축과 직각인 방향

| 속성 | 적용 대상 | 값 | 의미 |
|---|---|---|---|
| `display` | 컨테이너 | `flex` | 플렉스 컨테이너로 지정 |
| `flex-direction` | 컨테이너 | `row`(기본, 가로) / `row-reverse` / `column` / `column-reverse` | 주축 방향 결정 |
| `justify-content` | 컨테이너 | `flex-start` · `center` · `flex-end` · `space-between` · `space-around` · `space-evenly` | 주축 방향 정렬 |
| `align-items` | 컨테이너 | `stretch`(기본) · `flex-start` · `center` · `flex-end` | 교차축 방향 정렬 |
| `flex-wrap` | 컨테이너 | `nowrap`(기본, 넘침) / `wrap`(줄바꿈) | 공간이 부족할 때 줄바꿈 여부 |
| `gap` | 컨테이너 | 예: `20px` | 아이템 사이 간격 |

```css
.card-list {
  display: flex;
  flex-direction: row;
  justify-content: space-between;
  align-items: flex-start;
  gap: 20px;
  flex-wrap: wrap;
}
```

`justify-content`의 `space-between`/`space-around`/`space-evenly` 차이가 특히 헷갈렸다.

| 값 | 동작 |
|---|---|
| `space-between` | 양 끝에 붙이고 사이 간격만 고르게 |
| `space-around` | 각 아이템 좌우에 같은 여백을 주는 방식 (양 끝 여백이 사이 간격의 절반) |
| `space-evenly` | 바깥쪽 여백까지 포함해서 모든 간격을 완전히 동일하게 |

또 `align-items`는 기본값이 `stretch`라서, 아무것도 지정하지 않으면 카드 높이가 컨테이너 높이만큼 늘어나 전부 같아 보인다. 실습 코드에서는 설명(`.desc`)이 있는 카드만 내용만큼 길어지게 하려고 일부러 `align-items: flex-start`를 지정했다.

## 3. Grid — 칸을 그려두고 채우기

Flex가 "한 줄로 세우고 정렬"이라면, **Grid는 행과 열, 두 방향을 동시에 정해서 칸에 넣는 배치 방식**이다.

| 속성 | 적용 대상 | 값 | 의미 |
|---|---|---|---|
| `display` | 컨테이너 | `grid` | 그리드 컨테이너로 지정 (지정만 하면 열 1개가 기본) |
| `grid-template-columns` | 컨테이너 | 예: `repeat(3, 1fr)` | 열 개수·너비 정의 |
| `gap` | 컨테이너 | 예: `20px` | 행/열 아이템 간 간격 |

```css
.grid-list {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}
```

여기서 `fr`은 **남은 공간의 몫**을 뜻한다. `repeat(3, 1fr)`은 "같은 비율(1)을 가진 열을 3개 만든다"는 의미다. 행의 개수는 따로 지정하지 않았는데, 열을 정하면 행은 자동으로 결정되기 때문이다. 실습 코드에서는 아이템이 6개였으므로 `6개 ÷ 3열 = 2행`이 자동으로 생겼다.

## 4. Flex vs Grid 비교

| 구분 | Flex | Grid |
|---|---|---|
| 배치 방식 | 한 방향(1차원) 줄 세우기 | 행·열(2차원) 동시 배치 |
| 핵심 개념 | 주축 / 교차축 | 열(`grid-template-columns`) / 행 |
| 기준 | 콘텐츠(아이템) 크기 기준으로 배치가 결정됨 | 미리 그려둔 트랙(칸) 기준으로 배치가 결정됨 |
| 적합한 상황 | 가로 or 세로 한 줄 나열, 정렬 | 칸 단위 레이아웃(카드 그리드 등) |

### 4.1 실습 코드로 확인한 차이

실습 파일(`05_flex_grid.html`)에서 `.card-list`는 카드 3개를 Flex로, `.grid-list`는 카드 6개를 Grid로 배치했는데, 이 둘을 비교하면서 "1차원 vs 2차원"이 실제로 어떤 차이를 만드는지 체감할 수 있었다.

| 상황 | Flex (`.card-list`) | Grid (`.grid-list`) |
|---|---|---|
| 한 줄에 몇 개씩 배치할지 | 직접 열 개수를 정하지 않는다. `flex-wrap: wrap`을 주면 컨테이너 너비와 아이템 크기에 따라 알아서 줄바꿈되므로, 화면 크기에 따라 한 줄에 2개가 될 수도 4개가 될 수도 있다 | `grid-template-columns: repeat(3, 1fr)`로 **열 개수를 못박아둔다.** 아이템이 6개든 9개든 항상 3개씩 끊어서 다음 줄로 넘어간다 |
| 줄바꿈 시 정렬 기준 | 아이템 하나하나가 컨테이너 안에서 "정렬"되는 개념 (`justify-content`, `align-items`) | 미리 그려둔 칸(트랙)에 아이템을 "배치"하는 개념. 칸 자체의 크기는 `1fr`처럼 트랙 정의에서 정해진다 |
| 아이템 크기를 다르게 주고 싶을 때 | 개별 아이템에 `flex-grow`/`flex-basis`를 줘서 **비율로만** 조절 | `grid-column: span 2`처럼 **몇 칸을 차지할지 직접 지정** 가능 (실습에는 없었지만 구조상 가능한 부분) |
| 방향 축 개수 | 주축 하나만 신경 쓰면 됨 (교차축은 정렬에만 관여) | 가로(열)·세로(행) 두 방향을 동시에 설계 |

정리하면, **Flex는 "아이템을 기준으로" 배치가 결정**되고(그래서 화면 크기·아이템 크기에 따라 결과가 유동적), **Grid는 "미리 그려둔 칸을 기준으로" 배치가 결정**된다(그래서 몇 개가 오든 구조가 고정적)는 점이 가장 본질적인 차이라고 이해했다.

### 4.2 언제 무엇을 쓸지

| 상황 | 선택 |
|---|---|
| 네비게이션 메뉴, 버튼 그룹처럼 한 줄로 나열하고 정렬만 하면 되는 경우 | Flex |
| 카드 목록처럼 행·열이 명확한 격자(그리드) 레이아웃을 짜야 하는 경우 | Grid |
| 페이지 전체의 큰 뼈대(헤더/사이드바/본문/푸터)를 잡는 경우 | Grid |
| 그 뼈대 안에서 아이템 하나를 정렬하거나 줄 세우는 경우 | Flex |

## 마무리

오늘 실습에서 가장 크게 배운 건 **`display: flex`/`display: grid`는 아이템이 아니라 컨테이너에 준다**는 점, 그리고 Flex는 "한 줄 정렬", Grid는 "칸 배치"로 역할이 다르다는 점이다. `justify-content`의 세 가지 `space-*` 값 차이와 `fr` 단위는 아직 손에 완전히 익지 않아서, 나중에 레이아웃을 짤 때 이 글을 다시 찾아보며 표를 확인할 계획이다.
